    8. 身份验证与授权

    对于每个请求，都会出现两个不同的问题：

    • 用户是谁？这就是身份验证：用户已经用用户名和密码表明了身份，之后的每个请求都必须证明它来自该用户；
    • 用户是否有权访问这个页面？这就是授权：在案例研究中，只有角色为 ADMIN 的用户才能管理医生和客户。

    由于服务器是无状态的（第 6 章），身份证明必须随每个请求一起发送。这里使用 JWT 令牌 （[JSON Web Token]）：登录之后，服务器生成一个包含用户身份的令牌，并用一个密钥对其签名。令牌存储在 Cookie 中；浏览器在每个请求中把它发回；服务器验证签名。用户可以读取自己的令牌，但无法修改它：任何修改都会使签名失效。

    在 [Spring] 中，这两个问题由 [Spring Security] 处理，它是 [Spring] 家族中不同于 [Spring MVC] 的一个项目。[Spring Security] 是一条Servlet 过滤器链 （参见第 7 章），位于 [DispatcherServlet] 之前：每个请求在到达 [Spring MVC] 之前都要经过它。

    • 身份验证由一个过滤器处理，它在请求中查找令牌、验证令牌，并推导出已通过身份验证的用户——一个存储在请求的 [Authentication] 对象中的 安全上下文。对于 JWT 令牌，这个过滤器由 [resource server]（“资源服务器”）组件提供，它属于 [Spring Security]，其名称源自 [OAuth2] 协议：资源服务器是接受由另一个服务器（这里是它自己）生成的令牌的服务器；
    • 授权由另一个过滤器处理，它应用以 [Java] 为每个 URL 编写的规则（“此地址是公开的”“此地址需要已通过身份验证的用户”），以及应用于控制器的注解（[@PreAuthorize]，示例 26）。

    本章的示例多使用一个启动器：[spring-boot-starter-security-oauth2-resource-server]。它包含 [Spring Security]、其“资源服务器”组件，以及 [Nimbus JOSE + JWT] 库，该库用于生成和验证令牌。密码哈希（[bcrypt]）属于 [Spring Security]：无需再声明其他库。[Maven] 会在首次编译时下载这些库；因此需要互联网连接。

import java.util.List;
import java.util.Optional;

import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;

// 用户，存放在内存中（下一章会把它们放入数据库）
@Service
public class UsersService {

    public record User(String login, String name, String role, String passwordHash) {
    }

    private final List<User> users;

    // PasswordEncoder：密码的哈希（bcrypt，参见 SecurityConfig）
    public UsersService(PasswordEncoder hashing) {
        // 绝不保存密码本身，只保存其哈希
        users = List.of(
                new User("marie", "Marie Pélissier", "USER", hashing.encode("marie")),
                new User("admin", "Administrator", "ADMIN", hashing.encode("admin")));
    }

    public Optional<User> find(String login) {
        return users.stream().filter(u -> u.login().equals(login)).findFirst();
    }
}
    • 第 13–14 行：用户及其角色，以嵌套在服务内部的 record 的形式表示；

    package example25.auth;

import java.time.Duration;
import java.time.Instant;
import java.util.Optional;

import org.springframework.http.ResponseCookie;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.oauth2.jose.jws.MacAlgorithm;
import org.springframework.security.oauth2.jwt.JwsHeader;
import org.springframework.security.oauth2.jwt.JwtClaimsSet;
import org.springframework.security.oauth2.jwt.JwtEncoder;
import org.springframework.security.oauth2.jwt.JwtEncoderParameters;
import org.springframework.stereotype.Service;

import example25.auth.UsersService.User;

@Service
public class AuthService {

    // 承载令牌的 Cookie 的名称
    public static final String COOKIE = "token";

    private final UsersService users;
    private final PasswordEncoder hashing;
    private final JwtEncoder encoder;
    private final JwtProperties properties;

    public AuthService(UsersService users, PasswordEncoder hashing, JwtEncoder encoder,
            JwtProperties properties) {
        this.users = users;
        this.hashing = hashing;
        this.encoder = encoder;
        this.properties = properties;
    }

    // 用户，或者在登录名未知或密码错误时为“空”
    public Optional<User> validate(String login, String password) {
        if (login == null || password == null) {
            return Optional.empty();
        }
        return users.find(login).filter(u -> hashing.matches(password, u.passwordHash()));
    }

    // 用户的 JWT 令牌，用密钥签署
    public String createToken(User user) {
        Instant now = Instant.now();
        // 令牌的内容：“claims”（关于用户的声明）
        JwtClaimsSet claims = JwtClaimsSet.builder()
                .subject(user.login())
                .claim("name", user.name())
                .claim("role", user.role())
                .issuedAt(now)
                .expiresAt(now.plus(duration()))
                .build();
        // 头：签名算法（HMAC-SHA256）
        JwsHeader header = JwsHeader.with(MacAlgorithm.HS256).build();
        return encoder.encode(JwtEncoderParameters.from(header, claims)).getTokenValue();
    }

    // 承载令牌的 Cookie：页面的 JavaScript 无法读取它
    public ResponseCookie cookie(String token) {
        return ResponseCookie.from(COOKIE, token).path("/").httpOnly(true).sameSite("Lax").maxAge(duration()).build();
    }

    private Duration duration() {
        return Duration.ofMinutes(properties.durationMinutes());
    }
}

    我们来解释这段代码：

    • 第 22 行：携带令牌的 Cookie 的名称；
    • 第 29–35 行：该服务通过构造函数接收用户服务、密码编码器、令牌编码器 [JwtEncoder]、以及属性 [jwt.*]。后面这三个 Bean 在 [SecurityConfig] 中声明；
    • 第 38–43 行：登录名和密码验证。[Optional.filter] 在条件为 false 时清空容器：只有登录名存在并且当 [hashing.matches(password, hash)] 认可该密码时，结果才包含该用户；
    • 第 49–55 行：令牌的内容，即声明 （关于用户的陈述）。[subject] （声明 [sub]）是用户标识符的约定名称。我们在这里包含页面所需的内容（姓名、角色），这样就不必在每个请求时都查询数据库。[issuedAt] 和 [expiresAt] 提供声明 [iat] （创建日期）和 [exp] （过期日期）；
    • 第 57 行：令牌的头部，它指定签名算法：HMAC-SHA256，记为 [HS256]；
    • 第 58 行：编码器生成已签名的令牌；[getTokenValue()] 将其转换为文本形式；
    • 第 62–64 行：携带令牌的 Cookie，由 [ResponseCookie] 类生成，该类来自 [Spring]：[httpOnly(true)] 阻止页面上的 [JavaScript] 读取它，这样即使页面上执行了恶意脚本，令牌也受到保护；[sameSite("Lax")] 阻止浏览器在来自其他站点的 POST 请求中携带它（见下文的 [CSRF] 防护）；[maxAge] 将 Cookie 的有效期设置为与令牌的有效期一致。

// Spring Security 的配置
@Configuration
@EnableConfigurationProperties(JwtProperties.class)
public class SecurityConfig {

    // 用于签署和检查令牌的密钥（对称的 HMAC-SHA256 算法）
    @Bean
    public SecretKey jwtKey(JwtProperties properties) {
        return new SecretKeySpec(properties.secret().getBytes(StandardCharsets.UTF_8), "HmacSHA256");
    }

    // 令牌的构建（Nimbus 库，由 Spring Security 引入）
    @Bean
    public JwtEncoder jwtEncoder(SecretKey key) {
        return NimbusJwtEncoder.withSecretKey(key).algorithm(MacAlgorithm.HS256).build();
    }

    // 令牌的检查：签名和过期日期
    @Bean
    public JwtDecoder jwtDecoder(SecretKey key) {
        return NimbusJwtDecoder.withSecretKey(key).macAlgorithm(MacAlgorithm.HS256).build();
    }

    // 密码的哈希：bcrypt，代价因子为 10
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(10);
    }
    • 第 33 行：一个配置类，它的 [@Bean] 方法创建 Bean（参见示例 06）；
    • 第 34 行：将 [JwtProperties] record 注册为 Bean，由 [application.properties] 填充；
    • 第 38–41 行：签名密钥，由 [jwt.secret] 属性的文本生成。签署和验证令牌使用同一个密钥：该算法是对称的。[@Bean] 方法可以接受其他 Bean 作为参数：这里是属性 [jwt.*]；
    • 第 44–47 行：令牌编码器，使用密钥进行签名。[NimbusJwtEncoder] 依赖于 [Nimbus] 库；
    • 第 50–53 行：解码器，用于验证收到的每个令牌：首先验证签名（使用同一个密钥），然后验证过期时间（对时钟不同步允许 60 秒的容差）。身份验证过滤器对每个携带令牌的请求都会使用它；

        // 安全过滤器链：谁可以访问什么，以及如何
    // 识别用户
    @Bean
    public SecurityFilterChain securityFilters(HttpSecurity http) throws Exception {
        http
                // 1. 访问规则，按顺序检查
                .authorizeHttpRequests(access -> access
                        .requestMatchers("/", "/login", "/error", "/bootstrap/**").permitAll()
                        .anyRequest().authenticated())
                // 2. 通过 JWT 令牌进行身份验证（OAuth2“资源服务器”）
                .oauth2ResourceServer(jwt -> jwt
                        .bearerTokenResolver(tokenFromCookie())
                        .authenticationEntryPoint(toLogin())
                        .jwt(config -> config.jwtAuthenticationConverter(converter())))
                // 3. 没有令牌却请求受保护的页面：转到登录页面
                .exceptionHandling(errors -> errors.authenticationEntryPoint(toLogin()))
                // 4. 登出（POST /logout）：删除 Cookie，然后转到 /login
                .logout(logout -> logout.logoutUrl("/logout").deleteCookies(AuthService.COOKIE)
                        .logoutSuccessUrl("/login"))
                // 5. 服务器是无状态的：没有 HTTP 会话
                .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                // 6. 没有防 CSRF 令牌：SameSite=Lax Cookie 已经保护了
                // 来自其他站点的 POST 请求
                .csrf(csrf -> csrf.disable());
        return http.build();
    }

    // 令牌从 Cookie 中读取（而不是从 Authorization 头中读取）
    private static BearerTokenResolver tokenFromCookie() {
        return request -> {
            Cookie cookie = WebUtils.getCookie(request, AuthService.COOKIE);
            return cookie == null ? null : cookie.getValue();
        };
    }

    // 没有已通过身份验证的用户（没有令牌、令牌无效或已过期）：
    // 我们删除可能存在的 Cookie 并重定向到登录页面
    private static AuthenticationEntryPoint toLogin() {
        return (request, response, exception) -> {
            if (WebUtils.getCookie(request, AuthService.COOKIE) != null) {
                response.addHeader("Set-Cookie", ResponseCookie.from(AuthService.COOKIE, "").path("/").maxAge(0).build().toString());
            }
            response.sendRedirect("/login");
        };
    }

    // 从令牌到已通过身份验证的用户：[name] 声明是其姓名，
    // [role] 声明是其角色；Spring Security 以 ROLE_ 前缀书写角色
    private static JwtAuthenticationConverter converter() {
        JwtGrantedAuthoritiesConverter roles = new JwtGrantedAuthoritiesConverter();
        roles.setAuthoritiesClaimName("role");
        roles.setAuthorityPrefix("ROLE_");
        JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
        converter.setJwtGrantedAuthoritiesConverter(roles);
        converter.setPrincipalClaimName("name");
        return converter;
    }
}

    • 第 4–5 行：一个类型为 [SecurityFilterChain] 的 Bean：即安全过滤器链。[Spring Boot] 提供一个 [HttpSecurity] 对象，我们在构建过滤器链（第 26 行）之前逐个方法地对其进行配置。每个方法接收一个 lambda 来配置设置的一部分；
    • 第 8–10 行：URL 的访问规则，按以下顺序检查：[/]、[/login]、[/error] （[Spring Boot] 的错误页面）以及 [Bootstrap] 的文件是公开的（[permitAll()]）；任何其他 URL（[anyRequest()]）都需要已通过身份验证的用户。因此 [/profile] 页面受到保护，而无需在其控制器中写任何代码；
    • 第 12–15 行：基于 JWT 令牌的身份验证。默认情况下，资源服务器在请求的 [Authorization: Bearer ...] 标头中查找令牌：[JavaScript] 客户端或移动应用就是这样工作的。浏览器不会自己添加这个标头：因此要指示它从 Cookie 中获取令牌（第 13 行）。第 15 行改变了令牌映射到用户的方式（参见第 50–58 行）；
    • 第 14 行和第 17 行：身份验证入口点 （[authentication entry point]）在请求受保护页面而没有已通过身份验证的用户时被调用。默认情况下，响应是没有内容的 401 错误：这对 [JavaScript] 客户端很有用，但会让用户感到困惑。这里改为将用户重定向到登录页面。这里声明了两次：当请求包含被资源服务器过滤器拒绝的令牌时，该过滤器会直接调用它自己的入口点（第 14 行）；第 17 行则涵盖了请求受保护页面而没有令牌的情形；
    • 第 19–20 行：注销由 [Spring Security] 自身通过一个过滤器（[LogoutFilter]）处理，该过滤器拦截 [POST /logout]：它删除令牌 Cookie（[deleteCookies]）并重定向到 [/login]。无需任何控制器动作；
    • 第 22 行：[STATELESS]：[Spring Security] 不创建（HTTP）会话（参见第 6 章），也不使用会话来保留用户。每个请求都仅凭令牌来识别用户；
    • 第 25 行：[CSRF] 防护（[Cross-Site Request Forgery]，跨站请求伪造）被禁用。[CSRF] 攻击是指恶意网站诱使受害者的浏览器向我们的站点发送 POST 表单：浏览器会携带 Cookie，请求就会被视为已通过身份验证。默认情况下，[Spring Security] 要求每个 POST 表单都带有一个防 CSRF 令牌——一个恶意网站无法得知的隐藏字段。在这里，[SameSite=Lax] Cookie 就足够了：浏览器不会在源自其他站点的 POST 请求中携带它，因此该请求到达时没有已通过身份验证的用户。然而，任何携带 Cookie 的 GET 请求都不得修改任何数据（参见示例 21）：[Lax] Cookie 会随来自其他站点的链接一起发送；
    • 第 30–35 行：令牌解析器 （[BearerTokenResolver]）：一个单方法接口，这里写成 lambda，它返回请求的令牌，或者 [null]。[WebUtils.getCookie] 按名称查找 Cookie；
    • 第 39–46 行：入口点：重定向到 [/login] （第 44 行）。如果请求包含 [token] Cookie，则说明令牌无效（签名无效）或已过期：通过将其重置为空值且有效期为零来清除该 Cookie（第 41–43 行）。如果没有这一步，浏览器会在请求 [GET /login] 时再次发送被拒绝的令牌，过滤器又会拒绝它——从而导致重定向循环；
    • 第 50–58 行：从令牌到已通过身份验证的用户。对于 [Spring Security]，用户的权限是权限项 （[authorities]）：简单的字符串。默认情况下，资源服务器从令牌的 [scope] 声明中读取它们，并带有前缀 [SCOPE_]。这里改为从 [role] 声明中读取（第 52 行），并带有前缀 [ROLE_] （第 53 行），这是 [Spring Security] 对角色所期望的前缀：令牌中的角色 [USER] 变成权限项 [ROLE_USER]。第 56 行指明，用户名（[Authentication.getName()]）是声明 [name]，而不是 [sub]。

        return expected != null && input != null
                && expected.expires().isAfter(Instant.now())
                && expected.text().equalsIgnoreCase(input.trim());

        static String svg(String text) {
        StringBuilder svg = new StringBuilder();
        svg.append("<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"%d\" height=\"%d\" viewBox=\"0 0 %d %d\">"
                .formatted(WIDTH, HEIGHT, WIDTH, HEIGHT));
        svg.append("<rect width=\"100%\" height=\"100%\" fill=\"#f5f7fa\"/>");

        // 字符：每个字符都经过放大、倾斜、移位，每个点还
        // 被随机地略微移动
        double step = (WIDTH - 20) / (double) text.length();
        for (int i = 0; i < text.length(); i++) {
            double scale = random(4.6, 5.6); // 网格单位的大小，以像素为单位
            double angle = random(-0.35, 0.35); // 旋转角度，以弧度为单位（约 ±20°）
            double cx = 10 + step * (i + 0.5) + random(-3, 3); // 字符的中心
            double cy = HEIGHT / 2.0 + random(-4, 4);
            StringBuilder d = new StringBuilder();
            for (double[] stroke : FONT.get(text.charAt(i))) {
                for (int k = 0; k < stroke.length; k += 2) {
                    // 网格点，以 (2, 3) 为中心，经过扭曲、旋转、放置
                    double x = (stroke[k] - 2 + random(-0.2, 0.2)) * scale;
                    double y = (stroke[k + 1] - 3 + random(-0.2, 0.2)) * scale;
                    double px = cx + x * Math.cos(angle) - y * Math.sin(angle);
                    double py = cy + x * Math.sin(angle) + y * Math.cos(angle);
                    d.append(k == 0 ? 'M' : 'L').append(number(px)).append(' ').append(number(py)).append(' ');
                }
            }
            svg.append("<path d=\"%s\" fill=\"none\" stroke=\"%s\" stroke-width=\"%s\" stroke-linecap=\"round\" stroke-linejoin=\"round\"/>"
                    .formatted(d.toString().trim(), color(), number(random(2.2, 3))));
        }

        // 3 条噪声笔画：穿过图片的曲线
        for (int n = 0; n < 3; n++) {
            svg.append("<path d=\"M%s %s C%s %s %s %s %s %s\" fill=\"none\" stroke=\"%s\" stroke-width=\"1.3\"/>"
                    .formatted(number(random(0, 20)), number(random(5, 45)),

import java.time.Duration;
import java.time.Instant;
import java.util.HashMap;
import java.util.Map;

import org.springframework.stereotype.Service;

// 单例：统计每个 IP 地址的登录失败次数
@Service
public class LimiterService {

    private static final int MAX_FAILURES = 3;
    private static final Duration BLOCK_DURATION = Duration.ofMinutes(1);

    private static class Counter {
        int failures;
        Instant blockedUntil = Instant.MIN;
    }

    private final Map<String, Counter> counters = new HashMap<>();

    // synchronized：多个同时发生的请求，同一时刻只有一个访问

    // 剩余的封锁秒数（0：未被封锁）
    public synchronized long blockedSeconds(String ip) {
        Counter c = counters.get(ip);
        if (c == null) {
            return 0;
        }
        Duration remaining = Duration.between(Instant.now(), c.blockedUntil);
        return remaining.isNegative() || remaining.isZero() ? 0 : (remaining.toMillis() + 999) / 1000;
    }

    public synchronized void failure(String ip) {
        Counter c = counters.computeIfAbsent(ip, key -> new Counter());
        c.failures++;
        if (c.failures >= MAX_FAILURES) {
            c.blockedUntil = Instant.now().plus(BLOCK_DURATION);
            c.failures = 0; // 封锁结束后，我们从零重新开始
        }
    }

    public synchronized void success(String ip) {
        counters.remove(ip);
    }
}

    • 第 22 行：计数器字典由所有请求共享。它是一个简单的 [HashMap]，不支持并发访问：因此每个方法都是 [synchronized]。该关键字确保同一时刻只有一个线程执行对象的某个 [synchronized] 方法：两次同时发生的失败不会同时出现（参见第 6 章的 [AtomicInteger]）；

            limiter.failure(ip);
            return loginPage(model, login, "Incorrect login or password.");

        limiter.success(ip);
        response.addHeader(HttpHeaders.SET_COOKIE, auth.cookie(auth.createToken(user.get())).toString());
