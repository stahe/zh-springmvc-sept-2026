    12. 结论

    本文档描述了使用 [Spring MVC] 和 [Spring Boot] 框架开发 MVC Web 应用的过程：该应用的 HTML 页面由服务器使用 [Thymeleaf] 视图生成，客户端没有使用 [JavaScript] 框架。它逐步沿用了 [ASP.NET Core MVC] 课程，而该课程本身又建立在 [NestJS] 课程和《通过示例学习 ASP.NET MVC 入门》的基础之上：从控制器和路由到视图、表单、国际化、安全和数据访问，最后是一个完整的案例研究。

    因此，同样的 28 个示例和同一个应用，已使用三种框架编写：[TypeScript]、[C#]和 [Java]。概念是相同的；只有名称和机制不同。[ASP.NET Core MVC] 与 [Spring MVC] 之间的对应关系：

    关于 [ASP.NET Core]，需要注意的关键点是：

    • [Spring Boot] 根据可用的库来配置应用：只需添加一个 starter，就足以得到 Web 服务器、视图引擎、数据源或一条安全过滤器链，之后可以通过属性或声明自定义 Bean 来对其进行配置。这非常高效，前提是你知道 [Spring Boot] 为你做了什么：启动日志和 [DEBUG] 级别可以帮助你弄清楚这一点；
    • 许多行为依赖于代理：[@Transactional] 或 [@PreAuthorize] 只有在方法被另一个 Bean 调用时才会起作用。了解这一点很重要，这样你就不会措手不及；
    • [Spring Data JPA] 将 DAO 层简化为声明：一个接口、描述查询的方法名称，以及必要时的 [JPQL] 查询。乐观锁（[@Version]）以及将数据库错误转换为 [Spring] 异常的功能均已提供；
    • [Spring Security] 比 [ASP.NET Core] 中 [[Authorize]] 的特性更为冗长，但一切都可以在 [Java] 中的同一个地方进行配置：URL 的访问规则、令牌读取、重定向、登出以及 [CSRF] 防护；
    • [Thymeleaf] 视图是浏览器可以原样显示的有效 HTML 页面；它们只包含表达式，不含 [Java] 代码，这使它们保持简单。另一方面，它们不会被编译：表达式中的错误只有在页面显示时才会暴露，而不是像 [Razor] 那样在编译期间发现。

    该案例研究表明，不依赖 [JavaScript] 的经典 HTML 应用仍然是一种简单而稳健的解决方案：每个页面就是一个 URL，浏览器的“后退”按钮可以正常工作，一切都由服务器掌控。对 [JavaScript] 的有限使用（确认窗口）改善了用户体验，而应用的运行并不依赖它。

    欲了解更多信息，请参阅 [Spring Framework] （docs.spring.io/spring-framework/reference）的文档，以及 [Spring Boot]（docs.spring.io/spring-boot）、[Spring Security]（docs.spring.io/spring-security/reference）和 [Spring Data JPA] （docs.spring.io/spring-data/jpa/reference）的文档，以及 [Thymeleaf] 网站（thymeleaf.org），并将本应用与其对应的 [ASP.NET Core MVC] 和 [NestJS] 版本进行比较。
