    3. 动作模型

    动作需要浏览器发送的信息：URL 的参数（[?name=martin&age=42]）、表单字段、JSON 请求体，有时还有一个 HTTP 请求头。原课程把这组信息统称 为动作的模型。本章展示 [Spring MVC] 如何把这些信息提供给动作、把它们转换为正确的类型并加以验证。这一过程称为 数据绑定 （[data binding]）。

    术语说明：在 [Spring MVC] 中，“模型”（[Model]）一词主要指动作传递给其视图的数据（第 4 章“视图及其模型”）。本章所说的动作的模型，则是它 接收的内容。

    示例 07 至 12 与上一章的示例一样，都是文件夹 [Maven] [examples] 中的模块。你可以在该文件夹中打开终端并输入 [../mvnw spring-boot:run]（在 [..\mvnw spring-boot:run] 下为 [Windows]）来运行其中一个；[Ctrl-C] 停止服务器。每个示例都有一个名为 [application.properties] 的文件，内容类似下面这样：

    package example07.controllers;

import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/parameters")
public class ParametersController {

    // /parameters/action01?name=martin：URL 参数 [name] -> 操作参数 [name]
    // required = false：参数可以缺失，此时为 null
    @GetMapping("/action01")
    public String action01(@RequestParam(required = false) String name) {
        return "name = [%s], of type %s".formatted(name, name == null ? "null" : name.getClass().getSimpleName());
    }

    // /parameters/action02?age=42：值会被转换为参数的类型；
    // 没有 required = false 时，该参数是必需的
    @GetMapping("/action02")
    public String action02(@RequestParam int age) {
        return "age = [%d], of type int".formatted(age);
    }

    // /parameters/action03?age=42：Integer（而不是 int）接受 null 值
    @GetMapping("/action03")
    public String action03(@RequestParam(required = false) Integer age) {
        return "age = [%s]".formatted(age);
    }

    // /parameters/action04?page=2：参数缺失时使用默认值
    @GetMapping("/action04")
    public String action04(@RequestParam(defaultValue = "1") int page) {
        return "page = [%d]".formatted(page);
    }

    // /parameters/action05?q=spring：当 URL 参数的名称不同时，指定该名称
    @GetMapping("/action05")
    public String action05(@RequestParam(name = "q", required = false) String search) {
        return "search = [%s]".formatted(search);
    }

    // /parameters/action06?name=martin&age=42：一次获取所有参数
    @GetMapping("/action06")
    public Map<String, String> action06(@RequestParam Map<String, String> parameters) {
        return parameters;
    }
}

    我们来说明这段代码：

    • 第 16–17 行：注解 [@RequestParam] 把动作的一个参数与 URL 的一个参数（[?] 后面的部分，称为查询字符串，即 [query string]）关联起来。除非另有指定，URL 中的参数与 同名 ，即 [Java] 中的参数名：[name]。这个名称在运行时之所以可知，仅仅是因为 [Spring Boot] 的父项目指示编译器在编译后的代码中保留它（选项 [-parameters]）。注解可以接受具名参数，称为 属性：[required = false] 表示该参数可以省略；此时它等同于 [null]。第 18 行：方法 [formatted] 用后面的参数替换字符串 [%s] 中 的每一处；[name.getClass().getSimpleName()] 是该值所属类型的简短名称；
    • 第 23–24 行：该参数被声明为类型 [int]：[Spring MVC] 会把 收到的字符串（["42"]）转换成数字。如果没有 [required = false] 属性，[@RequestParam] 会使该参数成为 必需的：这是 [required] 的默认值。缺少参数，或者参数转换失败，都会导致 400 错误，并且不会执行动作；
    • 第 29–30 行：[int] 不可能等于 [null]。对于可选的数字，参数要声明为类型 [Integer]，即 [Java] 的类，它“包装”一个 [int] （[wrapper]）：[Integer] 对象可以取值 [null]，这样就能区分“没有年龄”和“年龄为 0”；
    • 第 35–36 行：[defaultValue] 属性提供参数缺失时使用的值（它同时也使该参数成为可选的）。它是一个字符串，转换方式与收到的值相同；
    • 第 41–42 行：当 URL 的参数名与 [name] 参数名不同时，属性 [Java] 用来指定 URL 参数的名称：动作的 [search] 参数接收 URL 中的 [q] 参数；
    • 第 47–48 行：标注了 [Map<String, String>] 类型的 [@RequestParam] 参数会接收 所有 URL 参数，不做转换：一个字典（参数名，值）。动作原样返回它，由 [Spring MVC] 把它序列化为 JSON。

    package example08.models;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

// 操作的模型：一个每个字段都带有其约束的类
public class PersonModel {

    @NotBlank(message = "the name is required")
    @Size(min = 2, max = 20, message = "the name must have 2 to 20 characters")
    private String name;

    @NotNull(message = "the age is required")
    @Min(value = 0, message = "the age must be between 0 and 150")
    @Max(value = 150, message = "the age must be between 0 and 150")
    private Integer age;

    @NotNull(message = "the title is required")
    @Pattern(regexp = "Mr|Mme|Melle", message = "unknown title")
    private String title;

    // 可选：没有 @NotNull
    @Email(message = "invalid email address")
    private String email;

    // 访问器（getter 和 setter）：模型绑定通过 setter 填充
    // 每个字段；JSON 序列化通过 getter 读取它
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }

    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
}

    我们来说明这段代码：

    • 第 3–9 行：验证注解，全部位于 [jakarta.validation.constraints] 包中；
    • 第 14–16 行：姓名是必填的且不能为空（[@NotBlank] 会拒绝 [null]、空字符串以及仅由空格组成的字符串），并且长度必须在 2 到 20 个字符之间（[@Size]）。每个注解都接受自定义的错误消息（属性 [message]）；
    • 第 18–21 行：年龄会被转换为整数，它是必填的（[@NotNull]），并且必须在 0 到 150 之间（[@Min]、[@Max]）。它被声明为 [Integer] 而不是 [int]，这样“没有年龄”（[null]）就会被 [@NotNull] 检测出来，而不是被设为 0；
    • 第 23–25 行：称谓必须匹配正则表达式 [Mr|Mme|Melle] （[@Pattern]）：它必须是这三个值之一；
    • 第 28–29 行：电子邮件地址是可选的（没有 [@NotNull]）；如果存在，则必须有效（[@Email]）。除 [@NotNull] 和 [@NotBlank] 之外的所有约束都接受值 [null]：这正是使字段成为可选的原因；
    • 第 33–43 行：访问器。按惯例，字段 [name] 的值由方法 [getName] （[getter]）读取，并由方法 [setName]（[setter]）写入。具有无参构造函数（这里是由 [Java] 隐式提供的构造函数）并且访问器遵循这一惯例的类，称为 JavaBean。这正是数据绑定所期望的形式：[Spring MVC] 使用无参构造函数创建对象，然后对请求中的每个参数，调用同名的 setter：对于 [setName("martin")] ，即 [?name=martin]，在把值转换为 setter 的类型之后调用。而 JSON 转换器则通过 getter 读取字段。

    package example08.controllers;

import java.util.LinkedHashMap;
import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import example08.models.PersonModel;
import jakarta.validation.Valid;

@RestController
@RequestMapping("/persons")
public class PersonsController {

    // /persons/action01?name=martin&age=42&title=Mr
    // @Valid：在操作运行之前先验证模型；如果模型
    // 无效，请求会被自动拒绝（400 错误）
    @GetMapping("/action01")
    public Map<String, Object> action01(@Valid PersonModel person) {
        Map<String, Object> response = new LinkedHashMap<>();
        response.put("person", person);
        response.put("ageType", person.getAge().getClass().getSimpleName());
        return response;
    }
}
    • 第 21 行：动作接收一个 [PersonModel]。该参数没有注解 [@RequestParam]：对于类型不是“简单”类型（字符串、数字、日期等）的参数，[Spring MVC] 隐含使用注解 [@ModelAttribute]，也可以显式写出。此时该参数是一个 命令对象 （[command object]），由数据绑定按刚才所述的方式创建并填充。与任何 setter 都不对应的查询参数会被忽略；
    • 第 21 行：注解 [@Valid] （来自 [jakarta.validation]）要求在对象被填充之后，通过检查其字段上的约束，来 验证该对象。如果数据绑定或验证失败，[Spring MVC] 会抛出 [MethodArgumentNotValidException] 异常：动作不会被执行，响应是 400 错误。这相当于 [[ApiController]] 特性在 [ASP.NET Core MVC] 中的作用；
    • 第 22–25 行：动作返回收到的人员及其年龄的类型。[LinkedHashMap] 是一个保持键插入顺序的字典：JSON 将按该顺序输出它们。

import org.springframework.http.MediaType;
import org.springframework.validation.BindingResult;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import example09.models.PersonModel;

@RestController
@RequestMapping("/persons")
public class PersonsController {

    // 紧跟在模型之后的 BindingResult 参数：操作总是会
    // 被执行，由操作决定如何处理无效的模型
    @GetMapping(value = "/action01", produces = MediaType.TEXT_HTML_VALUE)
    public String action01(@Valid PersonModel person, BindingResult result) {
        // result：模型的绑定和验证的结果
        if (!result.hasErrors()) {
            return "<p>Welcome %s %s (%d years old)</p>".formatted(person.getTitle(), person.getName(), person.getAge());
        }
        // 错误，逐字段列出
        String items = result.getFieldErrors().stream()
                .map(error -> "<li>%s: %s</li>".formatted(error.getField(), error.getDefaultMessage()))
                .collect(Collectors.joining());
        return "<p>The form contains errors:</p><ul>" + items + "</ul>";
    }
}

    我们来剖析这段代码：

    • 第 20 行：[produces] 属性（属于 [@GetMapping] ）设定响应类型：[MediaType.TEXT_HTML_VALUE] 是常量 ["text/html"]。因此，动作返回的字符串会作为 HTML 页面发送；
    • 第 21 行：动作有第二个参数，类型为 [BindingResult]，放在 紧接着 被验证的模型之后。它的出现改变了一切：发生绑定或验证错误时，[Spring MVC] 不再抛出异常；它把错误存放在这个 [BindingResult] 中，并且 执行动作，由动作决定如何处理这些错误。[BindingResult] 所起的作用与 [ModelState] 在 [ASP.NET Core MVC] 中相同；
    • 第 23–25 行：[hasErrors()] 表示是否存在错误。如果没有错误，则返回欢迎页面（[%d] 被替换为一个整数）；
    • 第 27–29 行：否则，返回错误列表。[getFieldErrors()] 返回与字段相关联的错误列表（[FieldError]），以及字段名（[getField()]）和消息（[getDefaultMessage()]）。处理过程使用来自 [Java] 流 （[Stream]）的 API：[stream()] 逐个生成列表项，[map] 转换每一项（这里是把一个错误转换成一行：HTML 的 [<li>]），[collect(Collectors.joining())] 把所有内容拼接成一个字符串。[map] 的参数是一个 lambda：一个匿名函数，写作 [parameter -> expression]；
    • 第 30 行：列出错误的页面。两种情况下，响应的状态码都是 200。

    package example12.binding;

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;
import java.time.format.ResolverStyle;

import org.springframework.core.convert.converter.Converter;

// 一个转换器：将法式日期 "23/09/2026" 转换为 LocalDate。
// 它将用于任何 LocalDate 类型的参数（参见 WebConfig）
public class DateFrConverter implements Converter<String, LocalDate> {

    // uuuu：年份；STRICT："31/02/2026" 会被拒绝（而不是被调整为 2 月 28 日）
    private static final DateTimeFormatter FORMAT =
            DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT);

    @Override
    public LocalDate convert(String text) {
        try {
            return LocalDate.parse(text, FORMAT);
        } catch (DateTimeParseException e) {
            // 失败：抛出异常，Spring 会将其转换为转换错误
            throw new IllegalArgumentException("[" + text + "] is not a valid dd/mm/yyyy date");
        }
    }
}
    • 第 12 行：转换器实现泛型接口 [Converter<S, T>]，其中 [S] 是源类型，[T] 是 目标类型：这里是从 [String] 到 [LocalDate] （不含时间的日期）；
    • 第 15–16 行：日期格式 [dd/mm/yyyy]。在 [STRICT] 模式下，不存在的日期（31/02/2026）会被拒绝；该模式要求把年份写成 [uuuu] 而不是 [yyyy]；
    • 第 19–21 行：该接口唯一的方法 [convert] 返回转换得到的日期；
    • 第 22–25 行：如果转换失败，转换器会抛出异常。[Spring MVC] 随即产生转换错误，就像 [?age=abc] 那样：对于 [@RequestParam] 是 400 错误，对于命令对象的字段，则是 [typeMismatch] 错误出现在 [BindingResult] 中。我们抛出的异常被保留为转换错误的 原因 ：我们将在控制器中取出它的消息。

    package example12.binding;

import org.springframework.core.MethodParameter;
import org.springframework.web.bind.support.WebDataBinderFactory;
import org.springframework.web.context.request.NativeWebRequest;
import org.springframework.web.method.support.HandlerMethodArgumentResolver;
import org.springframework.web.method.support.ModelAndViewContainer;

// 一个“参数解析器”：它为带有 @Language 注解的参数提供值，
// 该值读取自头 "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LanguageResolver implements HandlerMethodArgumentResolver {

    // 这个解析器是否处理该参数？
    @Override
    public boolean supportsParameter(MethodParameter parameter) {
        return parameter.hasParameterAnnotation(Language.class) && parameter.getParameterType() == String.class;
    }

    // 参数的值
    @Override
    public Object resolveArgument(MethodParameter parameter, ModelAndViewContainer mavContainer,
            NativeWebRequest request, WebDataBinderFactory binderFactory) {
        String header = request.getHeader("Accept-Language");
        String first = header == null ? "" : header.split(",")[0].trim();
        return first.length() >= 2 ? first.substring(0, 2).toLowerCase() : "fr";
    }
}
    • 第 11 行：解析器实现 [HandlerMethodArgumentResolver] 接口；
    • 第 14–17 行：对于它处理的参数，[supportsParameter] 返回 [true] ：这些参数带有注解 [@Language] 且类型为 [String]。[MethodParameter] 描述动作的一个参数；

// 一个“自制”的验证约束：@NoSpace。

@Target({ ElementType.FIELD, ElementType.PARAMETER })

    3.6.6. 结论

    动作模型是通过绑定请求中的数据构建的：URL 的参数和表单字段（[@RequestParam]、命令对象）、JSON 请求体（[@RequestBody]）、头（[@RequestHeader]），以及自定义解析器能够提供的任何内容。这些值会被转换为参数的类型，然后当模型带有 [Bean Validation] 约束并标注了 [@Valid] 时，依据这些约束进行验证。涉及 [@RequestParam] 的转换错误，或者没有 [BindingResult] 的无效模型，会导致 400 错误且不执行动作：这对 JSON 服务器是合适的。对于 HTML 应用程序，表单是一个标注了 [@Valid] 的 JavaBean，后面跟着动作要查询的 [BindingResult] 参数（示例 09），以便能够连同错误一起重新显示表单。这是下一章的主题。
