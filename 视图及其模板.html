    4. 视图及其模板

    到目前为止，动作都是自己生成响应：文本、JSON，以及用字符串写成的少量 HTML 标签。在 MVC 应用程序中，这是 视图的职责：一个描述 HTML 页面的文件，其中为动作传给它的数据——即 视图的模型——预留了占位符。[Spring MVC] 本身不提供视图语言：它可以与多种 视图引擎 （[Thymeleaf]、[FreeMarker]、[Mustache]、[JSP] 等）配合使用。本课程使用 [Thymeleaf]，它是与 [Spring MVC] 搭配使用最广泛的视图引擎，[Spring Boot] 可以自行对其进行配置。

    [Thymeleaf] 视图是一个标准的 [.html] 文件：一个有效的 HTML 文件，可以直接在浏览器中打开。数据通过以 属性 为前缀的额外 [th:] （[th:text]、[th:if]、[th:each] 等）插入其中，[Thymeleaf] 在服务器上执行这些属性，然后把它们从页面中移除。这就是 [Thymeleaf] 所说的 自然模板 （[natural templates]）：平面设计师无需启动应用程序就可以处理视图，开发人员再向其中添加 [th:] 属性。这与 [Razor]（[ASP.NET Core MVC] 的视图引擎）不同，后者把 HTML 和以字符 [C#] 代码混合在一起，代码之前要加上字符 [@]。

    package example13.controllers;

import java.time.LocalTime;
import java.time.format.DateTimeFormatter;
import java.util.Map;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.servlet.ModelAndView;

import example13.models.PageModel;

// @Controller：操作返回视图的名称
@Controller
public class ViewsController {

    private static final DateTimeFormatter TIME = DateTimeFormatter.ofPattern("HH:mm:ss");

    // Model：视图的模型，由操作填充的字典；
    // 返回的字符串是视图的名称：templates/views/index.html
    @GetMapping("/")
    public String index(Model model) {
        PageModel pageModel = new PageModel(
                "My first view",
                "This page was built by Thymeleaf, on the server.",
                LocalTime.now().format(TIME));
        model.addAttribute("model", pageModel);
        return "views/index";
    }

    // ModelAndView：将视图、其模型以及（如有需要）响应状态码放在同一个对象中
    @GetMapping("/hello/{name}")
    public ModelAndView hello(@PathVariable String name) {
        if (name.equals("unknown")) {
            return new ModelAndView("views/unknown", Map.of("name", name), HttpStatus.NOT_FOUND);
        }
        PageModel pageModel = new PageModel(
                "Hello " + name,
                "This time, the action built a ModelAndView object.",
                LocalTime.now().format(TIME));
        return new ModelAndView("views/index", Map.of("model", pageModel));
    }
}

    我们来说明这段代码：

    • 第 17 行：注解 [@Controller] 取代了前面示例中的注解 [@RestController] 。使用 [@RestController] 时，动作返回的 就是 响应（文本、JSON）。使用 [@Controller] 时，返回字符串的动作返回的是 视图名称：由视图来生成响应；
    • 第 25 行：动作接收一个类型为 [Model] 的参数，由 [Spring MVC] 提供。这就是视图模型：一个字典，其中每个条目（一个 属性）把一个名称与一个对象关联起来；
    • 第 26–30 行：动作创建一个 [PageModel] 对象（一个标题、一条消息、当前时间），并以名称 [model] 把它存入模型。视图将用这个名称取回它；
    • 第 31 行：动作返回视图的名称 [views/index]。它不再创建响应；它只是指向一个视图，并已准备好该视图的数据；
    • 第 36 行：动作 [hello] 返回一个 [ModelAndView] 对象，它把视图名称和它的模型合并为一个对象。这是编写使用视图的动作的另一种方式；
    • 第 38 行：当视图取决于请求时，由动作选择视图。这里，名称 [unknown] 显示视图 [views/unknown]，状态码为 404：[ModelAndView] 构造函数的第三个参数是响应码。该视图的模型只包含一个简单的字符串：所请求的名称。[Map.of(...)] 创建一个只读字典；
    • 第 44 行：这两个动作共用同一个视图 [views/index]，但模型不同。

    [Spring MVC] 到哪里去找视图 [views/index]呢？它把视图名称交给一个 视图解析器 （[ViewResolver]），由它把名称转换为具体的视图。[Spring Boot] 为 [Thymeleaf] 配置的那个解析器（[ThymeleafViewResolver]）会添加一个 前缀 [classpath:/templates/] 和一个 后缀 [.html]：视图 [views/index] 就是 [templates/views/index.html] 文件，位于 类路径中——也就是 [Java] 虚拟机查找应用程序的类和资源的文件夹与归档文件。项目的 [src/main/resources] 文件夹是其中的一部分：它的内容由 [Maven] 复制到 [target/classes]，与编译后的类放在一起。这两个值可以在 [application.properties] 中修改（属性 [spring.thymeleaf.prefix] 和 [spring.thymeleaf.suffix]）。与 [ASP.NET Core MVC] 不同，这里没有根据控制器和动作的名称推导视图名称的约定：动作总是指定视图的路径，相对于 [templates] 文件夹。项目文件如下：

    我们来说明这段代码：

    • 第 2 行：[Thymeleaf] 注释写作 [<!--/* ... */-->]。这是一个 HTML 注释，其内容由 [/*] 和 [*/] 括起来：[Thymeleaf] 会把它从渲染出的页面中移除，而普通的 HTML 注释（[<!-- -->]) 则会被发送给浏览器；
    • 第 3 行：[xmlns:th] 属性声明 [th:] 属性的命名空间。它仅供代码编辑器使用（自动补全、验证）：即使没有它，[Thymeleaf] 也会处理 [th:] 属性，并把它从生成的页面中移除；
    • 第 6 行：属性 [th:text] 用表达式的值替换标签的 内容。[${model.title}] 是一个 变量表达式：[model] 是由动作设置的模型属性，[.title] 调用它的访问器 [title()]。写在标签内部的文本“Page Title”只是一个示例，在直接用浏览器打开文件时显示；它会从生成的页面中消失；
    • 第 9–11 行：标题、消息和时间遵循相同的原则。要在一段文本中间插入一个值，请把它包在 [<span>] 标签中，该标签带有属性 [th:text]。

    [${...}] 表达式使用 [Spring] 表达式语言 [SpEL] （[Spring Expression Language]）编写。[model.title] 对 [getTitle()] 方法 [JavaBean] 调用，或者对 record 的 [title()] 方法调用：两种情况下写的代码相同。

    [Thymeleaf] 视图不会随应用程序一起编译：它是在请求页面时才被读取和解释的。因此，视图中的错误不会在编译时报告，而是在页面显示时才报告。如果你在视图中写入 [${model.titl}] ，请求就会失败（状态码 500），服务器控制台会显示：[Property or field 'titl' cannot be found on object of type 'example13.models.PageModel']。同样，与任何文件都不对应的视图名称会导致错误 [Error resolving template [views/missing], template might not exist or might not be accessible by any of the configured Template Resolvers]。在 http://localhost:5000/ 得到的结果：

    我们来说明这段代码：

    • 第 8 行：[th:with] 属性声明 局部变量 ，可以在包含它的标签及其所有子标签中使用——这里是 [total] 和 [count]——贯穿整个页面主体。[model.products.![price]] 是 [SpEL] 的投影：即产品价格列表。[#aggregates] 和 [#lists] 是 工具对象 ，属于 [Thymeleaf] （它们以 [#] 开头）：[#aggregates.sum] 计算一个数字列表的和；[#lists.size] 统计列表中的元素个数；
    • 第 10–11 行：一个 [Thymeleaf] 注释，它不会出现在生成的页面中；
    • 第 12 行：值 [null] （[${model.nickname}]）什么都不显示，也不会报错；
    • 第 14–15 行：[th:text] 会对 HTML 中的特殊字符 进行转义（[<] 变成 [&lt;]……）：文本按原样显示。[th:utext] （[unescaped text]）不转义地插入它：它会被解释为 HTML。[th:utext] 只用于应用程序自己生成的 HTML，绝不用于用户输入的数据：用户可能会向页面注入 HTML，甚至是 [JavaScript]（这种攻击称为 [XSS]，即 [cross-site scripting]）；
    • 第 17–18 行：一个条件。如果表达式为真，[th:if] 就保留标签（及其内容），否则就移除它；[th:unless] 则相反。没有 [th:else]：我们写出相反的条件；
    • 第 22 行：一个循环。属性 [th:each] 会对列表中的每一项重复包含它的标签——这里是 [<li>]——一次。[product] 是当前项；[stat] 是可选的，它是 迭代状态：[stat.index] （从 0 开始）、[stat.count] （从 1 开始）、[stat.size]、[stat.first]、[stat.last]、[stat.even]、[stat.odd]。在标签文本中，[[[${product.name}]]] 是一个 内联表达式：它像 [th:text] 一样插入经过转义的值，而不需要 [<span>] 标签（形式 [[(...)]] 则像 [th:utext] 一样不转义地插入）；
    • 第 23 行：条件运算符 [condition ? value1 : value2]。字面字符串写在单引号之间；
    • 第 24–25 行：[th:block] 是 [Thymeleaf] 特有的标签：它只用来承载 [th:] 属性，并会从生成的页面中消失，只留下它的内容。[stat.first] 和 [stat.last] 检查在循环中的位置；
    • 第 30–31 行：列表为空的情况。[#lists.isEmpty] 检查列表是否为空；对空列表执行 [th:each] 循环什么都不会产生；
    • 第 34 行：一个使用 [|...|] 来自 [th:with] 的变量的字面量替换，以及两个方法调用：[total.doubleValue()] 把 [BigDecimal] 转换为 [double]，而 [#numbers.formatDecimal(value, 1, 2)] 将数字格式化为小数点前至少一位、小数点后恰好两位；
    • 第 35 行：指向 [model.address.street] 的引用，以及工具对象 [#strings]，它汇集了字符串操作（[toUpperCase]、[isEmpty]、[contains]、[startsWith] 等）；

import org.springframework.web.bind.annotation.ModelAttribute;

import java.math.BigDecimal;
import java.text.NumberFormat;
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.FormatStyle;
import java.util.Currency;
import java.util.Locale;

import org.springframework.context.i18n.LocaleContextHolder;
import org.springframework.stereotype.Component;

// @Component("formats")：一个名为 [formats] 的 Bean，视图通过
// ${@formats.money(...)} 调用它
@Component("formats")
public class Formats {

    // "keyboard" -> "KEYBOARD"；Locale.ROOT：结果不依赖于语言
    public String uppercase(String text) {
        return text == null ? "" : text.toUpperCase(Locale.ROOT);
    }

    // 以某种货币表示的金额，采用请求语言的格式
    public String money(BigDecimal amount, String currency) {
        // 当前请求的语言，由 LocaleResolver 设置（参见 WebConfig）
        Locale language = LocaleContextHolder.getLocale();
        NumberFormat format = NumberFormat.getCurrencyInstance(language);
        format.setCurrency(Currency.getInstance(currency));
        return format.format(amount);
    }

    // 同上，以欧元表示
    public String money(BigDecimal amount) {
        return money(amount, "EUR");
    }

    // 以完整文字表示的日期，使用请求的语言："Friday, September 25, 2026"
    public String date(LocalDate day) {
        return day.format(DateTimeFormatter.ofLocalizedDate(FormatStyle.FULL).withLocale(LocaleContextHolder.getLocale()));
    }
}

    我们来说明这段代码：

    • 第 16 行：注解 [@Component] 把该类变成一个 Bean：[Spring] 在启动时找到它（就像找到控制器一样），创建它的实例并保存它。["formats"] 是该 Bean 的名称：视图将用这个名称来调用它；
    • 第 20–22 行：首字母大写。[Locale.ROOT] 使结果与用户的语言无关；
    • 第 25–31 行：以某种货币表示的金额，按照 请求的语言格式化。[LocaleContextHolder.getLocale()] （第 27 行）获取这种语言，它是一个由 [Locale] 对象，由 [Spring MVC] 在每个请求开始时设置。[NumberFormat.getCurrencyInstance] 提供该语言的货币格式：小数分隔符、千位分隔符和货币符号的位置；[setCurrency] 选择货币，货币由其国际代码标识（[EUR]、[USD]）；

    // LocaleResolver 设置每个请求的语言（Locale）；Spring 将其存放
    // 在 LocaleContextHolder 中，视图和辅助类可以在那里再次找到它
    static class LanguageParameterResolver implements LocaleResolver {

        @Override
        public Locale resolveLocale(HttpServletRequest request) {

        @Override
        public void setLocale(HttpServletRequest request, HttpServletResponse response, Locale locale) {
            throw new UnsupportedOperationException("the language is set by the URL");

        // 页面的路径，从当前请求中读取
        String path = context instanceof IWebContext web ? web.getExchange().getRequest().getRequestPath() : "";
        boolean isActive = value.equals("/") ? path.equals("/") : path.startsWith(value);
        if (isActive) {
            // 我们把 "active" 类添加到标签的 class 属性中
            String classes = tag.getAttributeValue("class");
            structure.setAttribute("class", classes == null ? "active" : classes + " active");
        }
    }
}

@Controller
public class BooksController {

    private static final List<Book> BOOKS = List.of(
            new Book("Le Rouge et le Noir", "Stendhal", "novel"),
            new Book("Les Fleurs du mal", "Baudelaire", "poetry"),
            new Book("Madame Bovary", "Flaubert", "novel"),
            new Book("Alcools", "Apollinaire", "poetry"),
            new Book("Le Cid", "Corneille", "drama"));

    private static final List<String> GENRES = List.of("novel", "poetry", "drama");

    // GET / 和 GET /search?keyword=...&genre=...：表单及其结果
    @GetMapping({ "/", "/search" })
    public String search(@RequestParam(required = false) String keyword,
            @RequestParam(required = false) String genre, Model model) {
        String word = keyword == null ? "" : keyword.trim().toLowerCase(Locale.ROOT);
        List<Book> results = BOOKS.stream()
                .filter(b -> word.isEmpty() || b.title().toLowerCase(Locale.ROOT).contains(word)
                        || b.author().toLowerCase(Locale.ROOT).contains(word))
                .filter(b -> genre == null || genre.isEmpty() || b.genre().equals(genre))
                .toList();
        model.addAttribute("model", new SearchModel(keyword == null ? "" : keyword,
                genre == null ? "" : genre, GENRES, results));
        return "books/search";
    }
}

       min, max. [errorOf]: the property whose error is displayed (name by default) */-->
<div class="mb-2" th:fragment="field" th:with="key=${errorOf ?: name}">
  <label class="form-label" th:for="${name}" th:text="${label}">Label</label>
  <!--/* __${name}__：预处理；先对 ${name} 求值，其结果
         ("email") replaces the expression: th:field="*{email}" */-->
  <input class="form-control" th:type="${type}" th:field="*{__${name}__}"
         th:classappend="${#fields.hasErrors(key)} ? 'is-invalid'"
         th:required="${required}"
         th:attr="maxlength=${maxlength},minlength=${minlength},min=${min},max=${max}">
  <!--/* 该字段的第一条错误消息，位于字段下方 */-->
  <div class="invalid-feedback" th:if="${#fields.hasErrors(key)}" th:text="${#fields.errors(key)[0]}">error</div>
</div>

    我们来解释这段代码：

    • 第 5 行：片段 [field] 被声明为没有签名——也就是没有参数列表。调用它时将使用命名参数（[field(name='age', label='Age', ...)]），这些参数会成为片段的变量；未提供的参数会被直接设置为 [null]。这对于带有许多可选参数的片段很有用。[th:with] 声明变量 [key]：即要显示错误的属性名。运算符 [?:] （称为“Elvis”）在其左操作数不为 [null] 时返回左操作数，否则返回右操作数：[errorOf] 若已提供则取它，否则取 [name]；
    • 第 9 行：[th:type] 写入属性 [type]。[th:field] 必须接收属性名，该属性名存储在变量 [name] 中。不能写 [*{name}] （那将表示属性 [name]）：而要使用预处理 [__...__]。双下划线之间的表达式会被首先求值，其结果替换该文本：如果 [name] 等于 [email]，则该属性变为 [th:field="*{email}"]，然后再按正常方式求值。[th:field] 使用表单对象（[th:object]），该对象由插入该片段的视图声明；
    • 第 10 行：[#fields.hasErrors(key)] 指示该属性在表单对象的 [BindingResult] 中是否有错误。然后 [Bootstrap] 的 [is-invalid] 类会将该字段高亮为红色；
    • 第 11 行：如果 [required] 为 true，则写入布尔属性 [required] ；否则省略它；
    • 第 12 行：[th:attr] 一次写入多个属性。值为 [null] 的属性不会被写入：每个字段只接收适用于它的 HTML5 约束；
    • 第 14 行：错误消息，位于字段下方（类 [Bootstrap] [invalid-feedback]）。[#fields.errors(key)] 返回该属性的消息列表；一个属性可能违反多个约束，而只显示第一个（[[0]]）。

    4.7.2. 浏览器验证

    属性 [required]、[maxlength]、[min]、[max]、[type="email"]…… 指示浏览器在提交表单之前对其进行验证：用户会立即通过工具提示得到通知，而无需与服务器进行任何往返通信。点击“enable it”链接（http://localhost:5000/register?html5=true）即可获得这种行为，它会从表单中移除 [novalidate] 属性。

    这种验证只是一种便利，而不是安全措施：只需使用浏览器的开发者工具删除 [required] 属性，或使用 [curl] 发送请求，就可以绕过它。服务器端验证仍然必不可少。这正是本示例默认禁用浏览器验证的原因：为了演示服务器的工作方式。不过，案例研究同时保留了两者：HTML5 属性用于提供便利，服务器端验证用于保证安全。

    4.8. 示例 20：Post/Redirect/Get 模式

    当 POST 表单成功提交时，动作可以直接显示一个页面。问题在于，如果用户随后刷新该页面（F5 键）：浏览器会重新提交表单，操作就会被执行第二次（订单被下了两次、预约被预约了两次……）。Post / Redirect / Get 模式（PRG）可以避免这个问题：成功的 POST 动作不生成页面；而是重定向到一个 GET 页面。重新加载该页面只会再触发一次 GET，不会产生任何影响。

    还剩下一个细节：GET 页面必须显示一条消息（“任务已添加”），尽管这条消息是由 POST 动作在另一个请求中生成的。[Spring MVC] 为此提供了闪现属性：这些属性在重定向之前设置，并保留到下一个请求，在那里它们被添加到模板中，然后消失。这称为闪现消息。默认情况下，[Spring MVC] 将闪现属性存储在用户的 HTTP 会话中：这是服务器为每个浏览器关联的一块内存空间（“数据作用域”一章专门讨论这一主题）。

    package example20.controllers;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import example20.services.TasksService;

@Controller
@RequestMapping("/tasks")
public class TasksController {

    private final TasksService tasks;

    public TasksController(TasksService tasks) {
        this.tasks = tasks;
    }

    // GET /tasks：列表和添加表单
    @GetMapping("")
    public String display(Model model) {
        model.addAttribute("tasks", tasks.list());
        return "tasks/tasks";
    }

    // POST /tasks：Post / Redirect / Get 模式
    @PostMapping("")
    public String add(@RequestParam(required = false) String label, Model model,
            RedirectAttributes redirect) {
        String text = label == null ? "" : label.trim();
        if (text.isEmpty() || text.length() > 40) {
            // 输入无效：我们不重定向，直接再次显示页面
            model.addAttribute("label", label);
            model.addAttribute("error", "The label must have 1 to 40 characters.");
            return display(model);
        }
        tasks.add(text);
        // 一个“闪现”属性：它会在重定向之后保留，供下一次请求使用
        redirect.addFlashAttribute("flash", "The task [" + text + "] has been added.");
        // 不返回页面：重定向到 GET 页面
        return "redirect:/tasks";
    }

    // POST /tasks/without-prg：反面示例（对 POST 直接返回页面）
    @PostMapping("/without-prg")
    public String addWithoutPrg(@RequestParam(required = false) String label, Model model) {
        tasks.add(label == null || label.isBlank() ? "(untitled)" : label.trim());
        model.addAttribute("withoutPrg", true);
        return display(model);
    }
}

    • 第 35–40 行：无效的输入——页面不经重定向而重新显示（必须保留输入内容和错误消息）。第 39 行只是像调用任何 [display] 方法一样调用 [Java] 方法：它把任务列表添加到模板中并返回视图名称；

    package example21.services;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

import org.springframework.stereotype.Service;

// 联系人，存放在内存中，由所有人共享（单例）
@Service
public class ContactsService {

    // 联系人：一个标识符、一个姓名、一个电话号码
    public record Contact(int id, String name, String phone) {
    }

    private final List<Contact> contacts = new ArrayList<>(List.of(
            new Contact(1, "Marie Durand", "01 23 45 67 89"),
            new Contact(2, "Paul Martin", "06 12 34 56 78"),
            new Contact(3, "Philippe Jandot", "02 98 76 54 32")));
    private int lastId = 3;

    // synchronized：同一时刻只有一个请求运行该方法
    public synchronized List<Contact> list() {
        return List.copyOf(contacts);
    }

    // Optional：一个联系人，或者在其不存在时为“空”
    public synchronized Optional<Contact> read(int id) {
        return contacts.stream().filter(c -> c.id() == id).findFirst();
    }

    public synchronized Optional<Contact> edit(int id, String name, String phone) {
        for (int i = 0; i < contacts.size(); i++) {
            if (contacts.get(i).id() == id) {
                // record 是不可变的：我们用一个新的来替换它
                Contact edited = new Contact(id, name, phone);
                contacts.set(i, edited);
                return Optional.of(edited);
            }
        }
        return Optional.empty();
    }

    public synchronized Contact add(String name, String phone) {
        Contact contact = new Contact(++lastId, name, phone);
        contacts.add(contact);
        return contact;
    }

    public synchronized Optional<Contact> delete(int id) {
        Optional<Contact> contact = read(id);
        contact.ifPresent(contacts::remove);
        return contact;
    }
}

    • 第 14–15 行：一个联系人；

    • 第 24 行：关键字 [synchronized] 确保同一时刻只有一个请求执行对象的 [synchronized] 方法：同时到达的请求不能同时修改该列表。这与示例 20 中的 [CopyOnWriteArrayList] 列表是不同的解决方案；

    package example21.controllers;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.server.ResponseStatusException;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import example21.services.ContactsService;
import example21.services.ContactsService.Contact;

@Controller
@RequestMapping("/contacts")
public class ContactsController {

    private final ContactsService contacts;

    public ContactsController(ContactsService contacts) {
        this.contacts = contacts;
    }

    // 一个链接（<a href>）：GET 请求，不修改任何内容
    @GetMapping("")
    public String list(Model model) {
        model.addAttribute("contacts", contacts.list());
        return "contacts/list";
    }

    @GetMapping("/{id:\\d+}")
    public String details(@PathVariable int id, Model model) {
        model.addAttribute("contact", contacts.read(id).orElseThrow(ContactsController::notFound));
        return "contacts/details";
    }

    // POST 表单中的一个按钮：修改数据的请求
    @PostMapping("/{id:\\d+}")
    public String save(@PathVariable int id, @RequestParam String name, @RequestParam String phone,
            RedirectAttributes redirect) {
        Contact contact = contacts.edit(id, name, phone).orElseThrow(ContactsController::notFound);
        redirect.addFlashAttribute("flash", "The contact [" + contact.name() + "] has been edited.");
        return "redirect:/contacts";
    }

    // 同一个表单，另一个按钮（formaction 属性）：另一个操作
    @PostMapping("/{id:\\d+}/duplicate")
    public String duplicate(@PathVariable int id, @RequestParam String name, @RequestParam String phone,
            RedirectAttributes redirect) {
        Contact copy = contacts.add(name + " (copy)", phone);
        redirect.addFlashAttribute("flash", "The contact [" + copy.name() + "] has been created.");
        return "redirect:/contacts";
    }

    @PostMapping("/{id:\\d+}/delete")
    public String delete(@PathVariable int id, RedirectAttributes redirect) {
        Contact contact = contacts.delete(id).orElseThrow(ContactsController::notFound);
        redirect.addFlashAttribute("flash", "The contact [" + contact.name() + "] has been deleted.");
        return "redirect:/contacts";
    }

    // 产生 404 响应的异常
    private static ResponseStatusException notFound() {
        return new ResponseStatusException(HttpStatus.NOT_FOUND, "unknown contact");
    }
}

    // 确认带有 data-confirmation="..." 属性的表单
// 没有 JavaScript 时，这些表单会不经确认直接发送。
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // 用户确认时要发送的表单

  // 1. 我们拦截需要确认的表单的提交
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // 提交被挂起
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // 窗口出现
    });
  });

  // 2. 窗口的两个按钮
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // 提交，且不再次触发 'submit' 事件
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • 第 3 行：代码被包装在一个立即执行的函数中，以避免创建全局变量；
    • 第 9–16 行：对每个带有属性 [data-confirmation] 的表单的提交都会被拦截。[preventDefault()] 会暂停提交；表单被保存下来，问题被放入窗口中（[textContent]，而不是 [innerHTML]：问题作为文本显示，绝不会被解释为 HTML），然后显示该窗口；
